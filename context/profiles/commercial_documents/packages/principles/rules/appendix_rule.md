# The appendix rule

A commercial document stays short because its main text carries only what the reader's decision depends on; everything a reader may want but the decision does not need goes to a named sub-section of an appendix, or out of the document. This file applies the four placement tiers of [reader_order.md](../../../../core/packages/whole_to_detail/rules/reader_order.md) — say now, make available, appendix, omit — to the main document and its appendices. The standard for what an appendix is for: detail that belongs in a specific sub-section of an appendix, which can be read when needed or out of particular interest.

## The main text reads completely without the appendices

A reader who never opens an appendix still understands the offer, the work or the agreement, and can decide or act on it. The test is to read the main text alone, straight through: every claim it makes is complete there, no sentence depends on an appendix to be understood, and no decision the main text asks for needs a fact that only an appendix holds. A fact the decision depends on stays in the main text, however detailed it is; a fact only some readers want, and on which the main line does not depend, moves.

Two typical examples mark the boundary. An inventory count of what is being migrated, and an operating rule for how unused hours are handled, are details that either need not be mentioned at all, or should be mentioned in a specific sub-section of an appendix. [catalogue.md](../../../../core/packages/anti_patterns/reference/catalogue.md) quotes them under entries 5 and 6 and sketches the rewrites: the main text names what is moved without the counts, and the rule moves unchanged into the appendix sub-section that holds the terms. The justification sentence that followed the rule is omitted, since it neither informs nor binds.

## An appendix is built from named sub-sections

An appendix is a set of sub-sections, each with a heading that names its content precisely enough that a reader looking for one fact finds it from the heading alone. An appendix that holds a single undifferentiated mass of moved detail fails the reader it exists for. Each sub-section opens with its own frame like any other section, per [commercial_document_principles.md](../reference/commercial_document_principles.md); an appendix is optional reading, and its sub-sections still follow the funnel.

The omit test of [reader_order.md](../../../../core/packages/whole_to_detail/rules/reader_order.md) is applied before the appendix test. Detail that no reader would understand, decide or do anything differently with goes out of the document, because moving it to an appendix only makes the document longer.

## An appendix is referenced from where it matters

The main text points to an appendix sub-section at the point where a reader may want the detail, by the sub-section's name. The pointer is short and names the content, so the reader knows what is there without opening it (illustrative):

> The retries and limits of error handling are described in Appendix B, section Error handling.

This is the narrow exception catalogue entry 5 allows: a navigational pointer that tells the reader where deferred detail lives. A pointer collected in a closing list of appendices, away from the text it serves, does not tell the reader when the detail is relevant; the closing list may still exist as an index, alongside the pointers in the text.

## Dependence runs one way

The main text never depends on an appendix, and an appendix may depend on the main text: it refines what the main text has established and does not restate it. Terms the main text defines keep their meaning in the appendix. Between an offer and its project description the same holds across documents, in the one direction that [commercial_document_principles.md](../reference/commercial_document_principles.md), § References between documents, allows: an appendix of the project description may be pointed to from the offer, and the project description never points to an appendix of the offer. An appendix is not written to serve both documents; each document's main text reads completely without the other's appendices.
