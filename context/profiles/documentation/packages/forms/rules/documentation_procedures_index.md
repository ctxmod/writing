# Consult the Documentation Library on Demand

The documentation profile carries a library governing how documentation is authored, structured, reviewed, and validated. Consult the relevant procedure or schema on demand rather than improvising one:

- the documentation-procedures index, organized by artifact type — the `procedures` package of this profile
- cataloging docs by type, audience, and maintenance status — <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::procedures@documentation/reference/inventory.md" />
- evaluating documentation organization patterns, redundancies, and findability — <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::procedures@documentation/reference/organization_assessment.md" />
- creating API reference documentation from source annotations and type definitions — <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::procedures@documentation/reference/api_documentation.md" />
- identifying code units lacking documentation by comparing source against existing docs — <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::procedures@documentation/reference/code_coverage_analysis.md" />
- visual documentation standards for architecture, sequence, and flow diagrams — <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::procedures@documentation/reference/diagram_standards.md" />
- authoring operational runbooks for maintenance, incidents, and deployments — <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::procedures@documentation/reference/runbook_creation.md" />
- the docs metadata schemas — <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::metadata@documentation/reference/frontmatter.md" />, <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::metadata@documentation/reference/file_naming.md" />, <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::metadata@documentation/reference/document_versioning.md" />
- pages drafted with assistance: verifying every statement about the product, and the filler that reads as generated — <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::forms@documentation/reference/assisted_drafts.md" />
- navigation structures for multi-document trees — <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::structure@documentation/reference/navigation.md" />
- alternative text, link text, headings, and color for readers using assistive technology (WCAG 2.2) — <ctxmod_path path="ctx:github.com/ctxmod/writing/context::shared::structure@documentation/reference/accessible_content.md" />
- planning documentation restructuring with dependency mapping and phased execution, coordinating subject-matter-expert review cycles and approval gates, and maintaining specification version history, change approvals, and deprecation paths — the `procedures` package of the `specification` profile (`migration_planning.md`, `sme_review.md`, `version_tracking.md`)
- specification organization schemas (file organization, normative language, and the document schema) and the technical specification file structure — the `structure` package of the `specification` profile
- answering "how do you know" for produced artifacts with real generated output, or a marked sketch when none exists — `evidence_by_example` in the `writing_context` module (profile `core`, package `basics`)
