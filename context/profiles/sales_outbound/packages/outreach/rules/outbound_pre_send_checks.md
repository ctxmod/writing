# Pre-send checks for sales messages

A sales message passes the correspondence pre-send checks in full ([pre_send_checks.md](../../../../correspondence/packages/message_doctrine/rules/pre_send_checks.md)), read for the sales situation as [outbound_pre_send_checklist.md](../reference/outbound_pre_send_checklist.md) sets out. The consuming repository's compliance controls run separately, and nothing here replaces them.

It also does not leave while the recipient has declined contact or a contact block applies; while suitability, authority or a required contact-rule check is missing; while it promises a demo, report or analysis that does not exist; or while it implies a relationship, a referral endorsement or a customer history that is not true. A statement about what the recipient feels, wants or will react to stays a hypothesis and never appears in the message as fact ([outbound_principles.md](../reference/outbound_principles.md), principle 7). The last question is whether the recipient has been given sufficient, correct and relevant reasons for exactly the step this message asks for.
