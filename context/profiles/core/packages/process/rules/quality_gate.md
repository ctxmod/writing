# Quality gate

Every draft of outward prose, such as a CV entry, a letter, an application answer, outreach, a profile, a proposal or web copy, passes this gate before it is reported as done, with or without a brief from an orchestrator. Run the parts in order.

1. Read the governing rules before the first sentence: the whole-to-detail model and review test, the anti-pattern catalogue, the basics, claims, reader, integrity and machine-tell rules, and the language and genre profiles for the text.
2. Self-review the finished draft against the same tests, as a reviewer would, and fix each finding or concede it with its reason. The `reader_pass` skill runs this step; its procedure is [reader_pass.md](../reference/reader_pass.md). Stop when the tests pass.
3. Where the consuming repository keeps a mechanical scan for greppable failures, run it over the changed text. A clean scan never clears a judgment finding.
4. A separate validating agent or pass runs the whole gate, not only its own brief.

Each part in full, with the files to read in step 1 and the stop rule, is in [standing_gate.md](../reference/standing_gate.md).
