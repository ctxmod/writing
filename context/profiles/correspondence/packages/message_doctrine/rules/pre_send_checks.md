# Pre-send checks

A message that reads well is checked before it leaves, scaled to the message. The consuming repository's own compliance controls (marketing law, personal data, send approval) run separately, and these checks replace none of them.

The message does not leave while any hard stop holds, however well the rest is written: an unverified fact its point rests on; an invented relationship or shared history; a result claim the sender cannot stand behind; a material limitation omitted where its absence misleads; a commitment the sender cannot keep; a recipient who has declined contact.

Before sending, run the checklist and the interchangeability, forwarding and answer-cost tests in [pre_send_checklist.md](../reference/pre_send_checklist.md); each unchecked point leads to a concrete change or a reasoned decision. The last question is whether the recipient has been given sufficient, correct and relevant reasons for exactly the step the message asks for, not whether the message sounds convincing.
